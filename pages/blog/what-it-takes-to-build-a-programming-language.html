It all starts here: Interpreters vs Compilers

To put it simply, both are tools for converting code from one form to other. The difference is how and when the code is executed.

  • Compilers: it reads the whole program in one go, translates into another form (machine code, bytecode) and produces an output (executable file) that can be run later.
  • Interpreters: it reads and executes the program directly line by line or by structure without creating a separate output.

The cool part is many modern languages blur these lines. Instead of a compile-only or interpret-only language, many compile source code into intermediate bytecode which is then executed by the interpreter. For example, Python actually compiles to bytecode (.pyc files), then interprets those files to produce output. Java compiles to bytecode, and then it runs on the JVM.

For BubbleLan, we went with the interpreter path because I wanted to keep it simple for the start.

The Four Stages

Let's take an example for printing statements in BubbleLan.

Stage 1: Lexical Analysis (The Lexer)

after completing each stage, you are advised to go through the whole code of that particular file for better understanding and reinforcing the logic. The link to repo will be provided at the end.

So the job of a lexer is to read a given input string character by character and group those characters into individual units called tokens.

There are two parts in a token: a value & a type. For ex. when you write "3" -- type is INTEGER and value is "3".

class Token:
    def __init__(self, type, value):
        self.type = type
        self.value = value
    def __repr__(self):
        return f'Token({self.type}, {self.value})'

the __repr__ method at the end is used for string representation of objects in python. So when you print a token, instead of seeing <Token object at 0x...>, you see something readable like Token(INTEGER, 5)

INTEGER, IDENT, ASSIGN, PLUS, MULTIPLY, DIVIDE, MINUS, SAY, EOF, GRT, LST, STRING, IF, THEN, ELSE, EQ, NEQ, FOR, IN, FROM, TO, COLON, LBRACKET, RBRACKET, COMMA = 'INTEGER', 'IDENT', 'ASSIGN', 'PLUS', 'MULTIPLY', 'DIVIDE', 'MINUS', 'SAY', 'EOF', 'GRT', 'LST', 'STRING', 'IF', 'THEN', 'ELSE', 'EQ', 'NEQ', 'FOR', 'IN', 'FROM', 'TO', 'COLON', 'LBRACKET', 'RBRACKET', 'COMMA'
  • This is me defining constants. Each name equals itself as a string. So INTEGER = 'INTEGER', PLUS = 'PLUS', etc. why? so that when I check token types later, I can write if token.type == INTEGER instead of if token.type == "INTEGER" -- no quotes, less error-prone.

I assume the token names are self-explanatory (IDENT = identifiers, GRT = Greater than, LST = Less than, EQ = '==', NEQ = '!=', LBRACKET = '[', RBRACKET = ']')

Next step, we move onto defining our main tokenizer class -- the heart of our program.

class Tokenizer:
    def __init__(self, txt):
        self.txt = txt
        self.pos = 0
        self.curr_char = txt[self.pos] if txt else None

Our Tokenizer (or lexer) takes in the source code as input string and initializes three things:

self.txt -- stores the entire source code || self.pos -- acts as index or position counter for the text || self.curr_char -- the character we're currently looking at

That if txt else None check is for handling the edge case of empty input. If someone passes an empty string, txt[0] would crash, so we set curr_char to None instead.

Now for traversing through the string input (our source code), we need to increment the pointer value everytime. Here's our pointer method -- for moving forward:

def pointer(self):
    self.pos += 1
    self.curr_char = self.txt[self.pos] if self.pos < len(self.txt) else None

everytime its called, value of self.pos will increase by 1 and self.curr_char would be set to the character at position self.pos. Whenever we consume a character, we call pointer() function.

Next method is: skip_whitespace() for skipping spaces, tabs, newlines which usually don't matter in programming languages. So whenever we encounter a whitespace, skip_whitespace() function calls self.pointer() which moves self.pos by 1.

Now we move onto reading numbers (digit by digit) and strings (everything b/w the quotes):

def number(self):
    result = ''
    while self.curr_char and self.curr_char.isdigit():
        result += self.curr_char
        self.pointer()
    return int(result)

def string(self):
    result = ''
    self.pointer()
    while self.curr_char and self.curr_char != '"':
        result += self.curr_char
        self.pointer()
    if self.curr_char == '"':
        self.pointer()
    return result

As pointer moves character by character through the whole input, whenever we encounter a digit, we call number() function. What it does is to keep appending characters to our result variable as long as they are digits. (and as mentioned self.pointer() will be called every time for moving the pointer forward). Once a non-digit character is found, we break the loop and return the final result variable, which will act as a one separate token in itself.

Next, for reading the strings, we have string() function. When we see a ", we know a string is starting. This method reads everything until the closing ". Works similar to the above number() function. (try to dry run it yourself)

Next comes a function for reading identifiers and keywords:

def identifier(self):
    result = ''
    while self.curr_char and self.curr_char.isalnum():
        result += self.curr_char
        self.pointer()
    if result == 'say':
        return Token(SAY, result)
    if result == 'if':
        return Token(IF, result)
    if result == 'then':
        return Token(THEN, result)
    if result == 'else':
        return Token(ELSE, result)
    if result == 'for':
        return Token(FOR, result)
    if result == 'in':
        return Token(IN, result)
    if result == 'from':
        return Token(FROM, result)
    if result == 'to':
        return Token(TO, result)
    return Token(IDENT, result)

This handles both variable names and keywords. The method reads a sequence of letters and numbers. (isalnum() function to check for alphanumeric characters) So if the result variable contains a keyword, the conditions within the if statements are executed. Else, it means that result contains a variable hence we return Token(IDENT, result)

Now comes our main function for this file, get_next_token():

def get_next_token(self):
    while self.curr_char:
        if self.curr_char.isspace():
            self.skip_whitespace()
            continue
        if self.curr_char.isdigit():
            return Token(INTEGER, self.number())
        if self.curr_char.isalpha():
            return self.identifier()
        if self.curr_char == '=':
            self.pointer()
            if self.curr_char == '=':
                self.pointer()
                return Token(EQ, '==')
            return Token(ASSIGN, '=')
        if self.curr_char == '!':
            self.pointer()
            if self.curr_char == '=':
                self.pointer()
                return Token(NEQ, '!=')
            raise Exception(f'Unknown character: !')
        if self.curr_char == '<':
            self.pointer()
            return Token(LST, '<')
        if self.curr_char == '>':
            self.pointer()
            return Token(GRT, '>')
        if self.curr_char == '+':
            self.pointer()
            return Token(PLUS, '+')
        if self.curr_char == '-':
            self.pointer()
            return Token(MINUS, '-')
        if self.curr_char == '*':
            self.pointer()
            return Token(MULTIPLY, '*')
        if self.curr_char == '/':
            self.pointer()
            return Token(DIVIDE, '/')
        if self.curr_char == '"':
            return Token(STRING, self.string())
        if self.curr_char == ':':
            self.pointer()
            return Token(COLON, ':')
        if self.curr_char == '[':
            self.pointer()
            return Token(LBRACKET, '[')
        if self.curr_char == ']':
            self.pointer()
            return Token(RBRACKET, ']')
        if self.curr_char == ',':
            self.pointer()
            return Token(COMMA, ',')
        raise Exception(f'Unknown character: {self.curr_char}')
    return Token(EOF, None)

such a long ass method!! Looks quite daunting but its not that complicated -- just a bunch of if statements combined together to check the conditions.

Input: say "Hello"

Tokenizer breaks it down:
Token(SAY, 'say')
Token(STRING, 'Hello')
Token(EOF, None)

and that's it! That's all what the parser needs to work with. We have successfully made our Lexer transform the string of characters into tokens.

Stage 2: Syntax Analysis (The Parser)

The process of recognizing a phrase or structure in stream of tokens is called parsing. The role of a parser is to check whether the tokens fit the defined grammatical rules of a language or not.

Before we move forward with the implementation, we need to define grammar for our language.

But what exactly is a grammar? A formal system of production rules used to generate a language. It defines a language by explaining what sentences it can form.

And what is a language? A set of strings conforming to those production rules -- which are rules that define grammar of a language.

I highly recommend to please go and have a good read on production rules before moving forward. won't be possible to explain on here soooo +_+

Parsers use these production rules during syntax analysis in different ways depending on their type. We will use Recursive descent parser -- a top-down parsing technique where a set of mutually recursive procedures is used to analyze an input string according to a grammar.

Before moving onto building parsers, we need to create a structure for our program. Abstract Syntax Trees or ASTs -- these create a structural representation of our program. The tree is called "Abstract" because it abstracts away unnecessary details (like parentheses or semicolons) and focuses on the logical structure of the code.

Let's have a look at how everything comes together:

Source code --> Lexer breaks the text into tokens --> Parser takes those tokens and organize them into a tree structure (AST) --> Interpreters walk through the AST and evaluate the nodes --> output is printed to the console.

These are the node types that form our syntax tree:

class Num:
    def __init__(self, value): self.value = value

    def __init__(self, value): self.value = value

    def __init__(self, name): self.name = name

    def __init__(self, name, value):
        self.name, self.value = name, value

    def __init__(self, expr): self.expr = expr

    def __init__(self, condition, then_branch, else_branch):
        self.condition, self.then_branch, self.else_branch = condition, then_branch, else_branch

    def __init__(self, elements): self.elements = elements

    def __init__(self, var, iterable, body):
        self.var = var

    def __init__(self, array, index):

Let's take a look at new_parser.py where our tokens become a tree:

The parser takes a lexer instance and immediately grabs the first token. self.curr_token is our look ahead -- the token we're currently examining.

class Parser:
    def __init__(self, lexer):
        self.lexer = lexer
        self.curr_token = self.lexer.get_next_token()

    def eat(self, token_type):
        if self.curr_token.type == token_type:
            self.curr_token = self.lexer.get_next_token()
        else:
            raise Exception(f'Expected {token_type}, got {self.curr_token.type}')

This is the parser's most basic operation. It says "I expect to see token type X here. If I do, consume it and move to the next token. If not, throw an error."

Example: When parsing an assignment, we do:

self.eat(IDENT)   # Must see a variable name
self.eat(ASSIGN)  # Must see '='

Here's where it gets interesting. Math has precedence rules: BODMAS. The parser needs to respect that. The trick is to use layers -- three methods that call each other in a hierarchy:

def factor(self):
    token = self.curr_token
    if token.type == INTEGER:
        self.eat(INTEGER)
        return Num(token.value)
    elif token.type == STRING:
        self.eat(STRING)
        return String(token.value)
    elif token.type == LBRACKET:
        return self.list_literal()
    elif token.type == IDENT:
        name = token.value
        self.eat(IDENT)
        if self.curr_token.type == LBRACKET:
            self.eat(LBRACKET)
            index = self.expr()
            self.eat(RBRACKET)
            return Index(Var(name), index)
        return Var(name)

def term(self):
    node = self.factor()
    while self.curr_token.type in (MULTIPLY, DIVIDE):
        op = self.curr_token.value
        if self.curr_token.type == MULTIPLY:
            self.eat(MULTIPLY)
        elif self.curr_token.type == DIVIDE:
            self.eat(DIVIDE)
        node = BinOp(node, op, self.factor())
    return node

def expr(self):
    node = self.term()
    while self.curr_token.type in (PLUS, MINUS):
        op = self.curr_token.value
        if self.curr_token.type == PLUS:
            self.eat(PLUS)
        elif self.curr_token.type == MINUS:
            self.eat(MINUS)
        node = BinOp(node, op, self.term())
    return node

When parsing: 2 + 3 * 4

expr() --> term() --> factor() returns Num(2)
sees +, creates BinOp
term() --> factor() returns Num(3)
  sees *, creates BinOp(Num(3), *, Num(4))
final BinOp: 2 + (3 * 4)

The result: 2 + (3 * 4) -- exactly what we want!

The layering of functions enforces precedence. This pattern is called recursive descent parsing and it's beautiful because the structure of code is imitating the structure of our grammar.

Also notice, in factor() method how we are handling array indexing. For example its a command like -- say nums[0]

The key insight is that after we consume the identifier token, we peek at what comes next. If it's [, we know more is coming; that its not a simple variable but it's an array access. If it's anything else (EOF or whatever), then it's just a variable reference.

This is called lookahead parsing -- looking at the next token to decide what to do. The curr_token is our lookahead -- it's always one token ahead of what we've actually consumed.

def list_literal(self):
    self.eat(LBRACKET)
    elements = []
    if self.curr_token.type != RBRACKET:
        elements.append(self.expr())
        while self.curr_token.type == COMMA:
            self.eat(COMMA)
            elements.append(self.expr())
    self.eat(RBRACKET)
    return Array(elements)

def comparison(self):
    node = self.expr()
    if self.curr_token.type in (EQ, NEQ, LST, GRT):
        op = self.curr_token.value
        token_type = self.curr_token.type
        self.eat(token_type)
        node = BinOp(node, op, self.expr())
    return node

list_literal() parses [1, 2, 3] or [x, y + 2, "hello"]. Start with an opening bracket [ --> parse expressions separated by commas till we don't encounter a closing bracket --> end with a closing bracket ]. Each element of a list can be any expression - that's why we call self.expr() for each one.

comparison() handles ==, !=, <, >. Parse an expression --> if we see a comparison operator --> parse another expression --> build a BinOp. Simple.

Again, try to spend a little time and dry run some case tests on these functions for better understanding.

Parsing Statements: this is where things happen

We have seen how to build expressions which produce values. But its actually the Statements that cause effects. They do the main stuff.

def assign_stmt(self):
    var_name = self.curr_token.value
    self.eat(IDENT)
    self.eat(ASSIGN)
    value = self.expr()
    return Assign(var_name, value)

def say_stmt(self):
    self.eat(SAY)
    expr = self.expr()
    return Say(expr)

def if_stmt(self):
    self.eat(IF)
    condition = self.comparison()
    self.eat(THEN)
    then_branch = self.statement()
    else_branch = None
    if self.curr_token.type == ELSE:
        self.eat(ELSE)
        else_branch = self.statement()
    return If(condition, then_branch, else_branch)

def for_stmt(self):
    self.eat(FOR)
    var_name = self.curr_token.value
    self.eat(IDENT)
    if self.curr_token.type == IN:
        self.eat(IN)
        iterable = self.expr()
    elif self.curr_token.type == FROM:
        self.eat(FROM)
        start = self.expr()
        self.eat(TO)
        end = self.expr()
        iterable = Range(start, end)
    else:
        raise Exception(f'Expected IN or FROM after for variable')
    self.eat(COLON)
    body = [self.statement()]
    return For(var_name, iterable, body)

def statement(self):
    if self.curr_token.type == IDENT:
        return self.assign_stmt()
    elif self.curr_token.type == SAY:
        return self.say_stmt()
    elif self.curr_token.type == IF:
        return self.if_stmt()
    elif self.curr_token.type == FOR:
        return self.for_stmt()
    else:
        raise Exception(f'Unexpected token {self.curr_token.type} in statement')

def program(self):
    statements = []
    while self.curr_token.type != EOF:
        statements.append(self.statement())
    return statements

Not to worry, you will understand how straightforward these are once you get the pattern. In case you forgot, have a look at our Abstract Syntax Tree in my_ast.py.

The beauty of this design is how it scales so well. Want to add while loops? Add a while_stmt() method and a case in statement(). Want dictionaries? Add dict_literal() and call it from factor(). Want functions? Add fun_stmt() and a Call node.

Everything follows the same pattern:

consume expected tokens --> recursively parse the sub-parts --> build a node

And once you have the AST, you've captured the structure perfectly. Now it doesn't matter if we write x = 5 + 2 or x=5+2; both will produce identical syntax trees because our parser strips away all the formatting noise and lefts pure meaning.

Stage 3: Execution (The Interpreter)

The lexer and parser did all the heavy lifting.

They transformed our source code (text) into a clean, structured tree. The final part is building an interpreter that will walk through our tree and do exactly what each node says.

The interpreter doesn't need to worry about syntax, precedence, or grammar rules. All of that has been solved. It just needs to answer one question for each node: "What do you do?"

Because by the time we are reaching execution, the problem has been simplified dramatically. We're not parsing text anymore -- we're just traversing a tree and following instructions.

Let me show you how stupidly simple this becomes.

The interpreter is basically a tree walker with memory.

class Interpreter:
    def __init__(self):
        self.env = {}

    def goto(self, node):
        method_name = 'goto' + type(node).__name__
        return getattr(self, method_name)(node)

We have self.env which acts as a memory for our program. Every variable you create lives here. So when we say x = 5 it means env['x'] = 5.

The goto() method is clever: it looks at what type of node it received and automatically calls that particular method. Got a Num node? Calls gotoNum(). Got a BinOp? Calls gotoBinOp().

This pattern (called the Visitor Pattern) keeps our code clean where each node type gets its own handler.

Next comes the heart of our expression evaluation:

def gotoBinOp(self, node):
    left = self.goto(node.left)
    right = self.goto(node.right)
    if node.op == '+':
        if isinstance(left, str) or isinstance(right, str):
            return str(left) + str(right)
        return left + right
    elif node.op == '-':
        return left - right
    elif node.op == '*':
        return left * right
    elif node.op == '/':
        return left / right
    elif node.op == '==':
        return left == right
    elif node.op == '!=':
        return left != right
    elif node.op == '<':
        return left < right
    elif node.op == '>':
        return left > right

See what happens with nested expressions, when you evaluate 2 + 3 * 4:

gotoBinOp(2 + (3*4))
  --> left = gotoNum(2) = 2
  --> right = gotoBinOp(3*4)
      --> left = gotoNum(3) = 3
      --> right = gotoNum(4) = 4
      --> 3 * 4 = 12
  --> 2 + 12 = 14

Also notice the string concatenation check -- if either side is a string, we convert both to strings and concatenate. This lets you do "x is " + 5 and get "x is 5".

Executing Statements: Making things happen

def gotoAssign(self, node):
    self.env[node.name] = self.goto(node.value)

def gotoSay(self, node):
    print(self.goto(node.expr))

def gotoIf(self, node):
    condition = self.goto(node.condition)
    if condition:
        return self.goto(node.then_branch)
    elif node.else_branch is not None:
        return self.goto(node.else_branch)

def gotoArray(self, node):
    return [self.goto(elem) for elem in node.elements]

def gotoRange(self, node):
    start = self.goto(node.start)
    end = self.goto(node.end)
    return list(range(start, end + 1))

def gotoIndex(self, node):
    array = self.goto(node.array)
    index = self.goto(node.index)
    return array[index]

def gotoFor(self, node):
    iterable = self.goto(node.iterable)
    for value in iterable:
        self.env[node.var] = value
        for stmt in node.body:
            self.goto(stmt)

The REPL: Interactive Programming

REPL stands for Read-Eval-Print Loop. It's an interactive shell where you type code line by line and see results immediately. Python has one (with python command). Node.js has one. And now BubbleLan has one too :D

Not to worry, REPL is just a while loop.

it reads input, executes it, prints the result and loop again.

def repl():
    print("Welcome to BubbleLan REPL!")
    print("Type 'q' to exit")
    interpreter = Interpreter()
    while True:
        try:
            code = input(">>> ")
            if code.strip() in ['q', 'quit', 'exit']:
                print("byee!")
                break
            if not code.strip():
                continue
            lexer = Tokenizer(code)
            parser = Parser(lexer)
            ast = parser.program()
            for node in ast:
                interpreter.goto(node)
        except KeyboardInterrupt:
            print("\nUse 'q' to exit")
        except Exception as e:
            print(f"Error: {e}")

And that's all. A REPL is just an infinite loop that reads, evaluates, and prints.

But notice we create interpreter = Interpreter() once before the loop, not inside it. This is crucial. This means the interpreter persists across lines. Variables you define will stick around and environment dictionary keeps growing as you add more variables.

If we created a fresh interpreter for each line, every variable would disappear immediately after you define it. (try to dry run the code yourself in order to understand what i'm talking about)

Running Files: The Script Mode

Having your own file extension sounds cool hence we need a program to run actual .bub files.

def run_file(filename):
    try:
        with open(filename, 'r') as f:
            code = f.read()
        lexer = Tokenizer(code)
        parser = Parser(lexer)
        ast = parser.program()
        interpreter = Interpreter()
        for node in ast:
            interpreter.goto(node)
    except FileNotFoundError:
        print(f"Error: File '{filename}' not found")
    except Exception as e:
        print(f"Error: {e}")

Even simpler than the REPL! No loop needed because we're running the entire file in one shot.

If anything goes wrong -- file doesn't exist, syntax error, runtime error -- we catch it and print a helpful message.

The key difference from REPL mode: we read everything at once, then execute it all. The REPL reads line by line. File mode reads the whole file, parses it completely, then executes the entire AST.

The Command-Line Interface

Now we need to tie it all together -- decide whether to run a file or start the REPL based on what the user typed:

def main():
    if len(sys.argv) == 1:
        repl()
    elif len(sys.argv) == 2:
        if sys.argv[1] in ['-h', '--help']:
            print_help()
        else:
            run_file(sys.argv[1])

main()

Here's the logic: no arguments = REPL, one argument = run that file. this gives you both modes of operation. Want to experiment? REPL. Want to run a script? File mode.

Installing BubbleLan system-wide

#!/bin/bash
echo "Installing BubbleLan..."
INSTALL_DIR="/usr/local/bin"
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
sudo ln -sf "$SCRIPT_DIR/bubblelan" "$INSTALL_DIR/bubblelan"
echo "BubbleLan installed successfully!"

The script creates a symbolic link (or a shortcut) in bin that points to your actual bubblelan file. This directory is already in your system's PATH, so now you can type bubblelan from anywhere.

The sudo ln -sf command: sudo = admin permission, ln = create link, -s = symbolic (shortcut, not copy), -f = force (overwrite if exists)
